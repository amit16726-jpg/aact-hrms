# AACT HRMS — system audit, 22 October 2026 (version 1.12.0 → 1.13.0)

Scope: database (85 tables, 259 API functions → 266), security model, MG pay confidentiality, cloud project advisors,
front end (bundle, dependencies, accessibility checks), deployment scripts, reporting coverage.
Method: Supabase security and performance advisors on the cloud test project, a scan of every `public.hr_*` function for a
permission check, dependency audit (`npm audit`), bundle analysis, the full automated test suites, and a review against
common HRMS expectations (reports, sign-in security, session handling).

## Summary

| # | Finding | Severity | Result |
|---|---|---|---|
| 1 | No report centre: only 4 fixed reports, no Excel / PDF downloads, no board pack, no scheduled reports | High (functional gap) | **Fixed** — 59 reports in 6 groups, Excel + PDF for every report, PowerPoint board pack, monthly scheduled reports |
| 2 | No two-step sign-in (MFA); a stolen password gives full access to salaries and personal data | High | **Fixed** — authenticator-app sign-in for everyone; enforced on the server; can be required for chosen roles |
| 3 | No automatic sign-out; an unlocked office PC stays signed in | Medium | **Fixed** — sign-out after 30 minutes without activity (5–480, Settings → Security), one-minute warning, works across tabs |
| 4 | Leftover schema `seed_tmp` on the cloud test project (helper tables of the old demo seed with 60 fictitious people) | Medium (hygiene) | **Fixed** by the 1.13.0 SQL file (`drop schema seed_tmp`) |
| 5 | 19 foreign keys without an index (advisor) | Low (performance) | **Fixed** — indexes added, plus indexes for audit-log, access-log and attendance-date queries used by reports |
| 6 | Main JavaScript bundle 745 kB | Low (speed on phones) | **Fixed** — split into cached vendor chunks; main chunk 336 kB; report libraries load only when a file is made |
| 7 | New report libraries pulled in packages with known advisories (jsPDF ≤ 4.2.0, image-size, uuid) | Medium | **Fixed** — jsPDF 4.2.1, safe overrides for image-size and uuid; `npm audit`: 0 vulnerabilities |
| 8 | Leaked-password protection is off on the cloud project | Medium | **Your action** — Supabase dashboard → Authentication → Password security → turn on "Leaked password protection" (paid plan) |
| 9 | "Signed-in users can execute SECURITY DEFINER functions" (259 notices) and "RLS enabled, no policy" (85) | Info | By design: tables are closed; every function checks the permission itself (re-verified: every function without `require_perm` filters rows through `visible_employees` or `document_scope`) |
| 10 | "Unused index" notices (41) | Info | Expected on a database without live data; review after three months of use |

No defects were found in the existing maker-checker rules, MG confidentiality or audit trail; the 9 existing test suites and the
new report and security suites all pass.

## What changed in 1.13.0

**Reports** (see `docs/REPORTS.md` for the full list)
- Workforce (12): headcount by department, employee list, joiners, leavers, turnover by month and by department, nationality, age,
  length of service, contracts ending, probation ending, managers and team sizes.
- Payroll and end of service (15): payroll register, by department, by cost centre, pay items, month-on-month variance, bank summary and
  list, SPF contributions, gratuity liability, loans outstanding, 12-month cost trend, salary changes, final settlements, salary listing,
  one-off pay items.
- Time and leave (10): attendance summary, late arrivals, absences, missing punches, overtime and overtime by department, leave
  balances, annual leave liability, leave taken, leave by type.
- Compliance (6): Omanisation by department and by profession, document expiries, missing mandatory documents, expatriate residence and
  permits, expatriates in Omani-only jobs.
- Talent and people operations (11): recruitment pipeline, time to hire, performance ratings and distribution, training completed and
  by course, certificates expiring, disciplinary cases, work injuries, assets with employees, exits.
- Audit and control (5): audit trail, sensitive-data access log, users and roles (access review), approvals log (maker-checker),
  control exceptions (self-approval, payroll steps by one person).
- Formats: on-screen preview with totals; **Excel** (formatted, filters, frozen header, number formats, right-to-left in Arabic);
  **PDF** (A4, header, filters, page numbers, confidentiality line, Arabic exact); **PowerPoint board pack** with editable charts.
- Scheduled reports: monthly in-app and e-mail reminders with a link (no personal data in e-mails), only to people allowed to see the report.

**Security**
- Two-step sign-in (TOTP): Settings → Two-step sign-in. Once on, every database call needs a session that passed the second step
  (`aal2`) — checked in `hr.require_user`, `hr.require_perm` and `hr.has_perm`, so it cannot be skipped from the browser.
  Settings → Security can require it for chosen roles (administrator must set it up first, so nobody locks the system).
- Automatic sign-out after inactivity (default 30 minutes).

## Recommendations (not changed)
1. Turn on leaked-password protection (finding 8) and require two-step sign-in for Super administrator, HR manager, Finance and
   Management payroll before go-live.
2. Agree the report pack with management: which scheduled reports go to whom (suggested: W01 + W05 monthly to the GM; P02 + P08 +
   P09 monthly to Finance; C01 + C03 monthly to HR; A03 quarterly to Internal Audit for the access review).
3. Keep the parallel payroll run (two months) as the go-live test of the payroll reports against the old system.
4. Review unused indexes after three months of live use.
